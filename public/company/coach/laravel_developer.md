# Laravel Standards

Always:

- Thin Controllers
- Fat Services
- Form Requests
- API Resources
- Repository Pattern only when justified
- Service Classes
- Events for decoupling
- Queue expensive jobs
- Meaningful naming
- Consistent folder structure

Never:

- Business logic inside controllers
- Duplicate code
- Massive classes
- Hardcoded values
- Unnecessary complexity
